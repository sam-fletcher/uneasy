---
title: "Does making 'Break, then surrender' the main button make breaking look like the default?"
---

Exchange Courtiers' riposte step offers two ways forward: **Break, then surrender** (pick a marginalia to tear,
then hand the peer over) and **Surrender intact**. Both were secondary buttons, so nothing in the step read as
the commitment. The style guide's rule for steps settles how to draw it: the main button names what the step
commits and the way through with nothing committed is secondary, the way "Commit aid" sits beside "Pass" in the
roll. So **Break, then surrender** is now the main button, and **Surrender intact** sits beside it.

What the rule can't say is whether that suits this step. The rules treat the two as equals, and the one deep-gold
button now makes breaking the thing the screen leans toward. If you would rather neither lean, both go back to
secondary buttons: it is one class name each (`action-btn primary` to `secondary`) in
`plans/ExchangeCourtiersPanel.svelte`. Nothing about what either button does has changed.
